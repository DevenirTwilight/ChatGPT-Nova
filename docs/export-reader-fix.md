# Real-page conversation reader compatibility (2026-10-05)

A user device reported “页面未提供完整消息树”. The old implementation called the backend directly with same-origin cookies and observed only an exact fetch URL. This did not reuse the website's authenticated/project-aware conversation reader. The screenshot does not establish the precise HTTP status or site-build variant on that device.

The public ChatGPT conversation-small module currently exports a read-only conversation loader with `includeFullConversation`, `forceNetworkFetch`, `signal`, and `onConversationLoadedFromNetwork`. The loader itself handles authorization and project context. Export now discovers this reader from the website's already loaded, approved-origin conversation module using function structure rather than a fixed CDN hash or minified export name. It requests the full current conversation and takes the raw network tree before site normalization. Nova does not read credentials, request headers, cookies, tokens, account state, or other conversations. Existing response observation/direct-request fallback remains available when that site reader is unavailable. URL object fetch arguments are now supported too.

Every tree still goes through root/parent/child/terminal and current DOM consistency validation. A mismatching reader response invalidates previously cached data. There is no visible-DOM-only fallback. HTML, Markdown, PDF, native saving/sharing, ComposerWebView, and WebShareAdapter remain unchanged.

Local verification: debug APK, Android test APK and lint built successfully; 25 core tests passed; existing Chromium export/render tests passed; new real-browser module-discovery test passed (direct API 401, project URL, full 400-message branch, duplicate export aliases, missing ancestor rejection, wrong conversation rejection, unavailable-reader rejection). No new Android emulator result is claimed here; the previously documented Android 33 performance failure remains unresolved.
